# Vue Auth-API Analyzer — Codex Instructions

> ⚠️ You MUST use the provided script pipeline. Do NOT manually analyze Vue source code.

## What This Tool Does

Scans Vue 3 projects for buttons with permission directives (e.g. `v-auth`), traces their backend API calls, and generates a complete **Button → Permission → HTTP API** mapping report.

## Installation

Before running analysis, ensure the tool is installed. **If not installed, install it for the user automatically:**

```bash
cd <project-root>
npm install --save-dev vue-auth-analyzer
```

Verify installation:

```bash
npx vue-auth-analyzer --help
```

Alternative: run without installing (auto-downloads on first use):

```bash
npx vue-auth-analyzer --run-ai
```

### LLM Credentials

Check if credentials are configured:

```bash
echo $OPENAI_API_KEY $AI_API_KEY $DEEPSEEK_API_KEY
```

If empty, ask the user to set one:

```bash
export OPENAI_API_KEY=sk-xxx    # OpenAI
export DEEPSEEK_API_KEY=sk-xxx  # DeepSeek
export AI_API_KEY=sk-xxx        # Generic
```

## Prerequisites

- Node.js ≥ 22
- LLM API credentials (auto-detected from env vars)

## Execution

### Step 1: Run Analysis

Run ONE command in the user's Vue project root:

```bash
cd <project-root> && npx vue-auth-analyzer --run-ai
```

Or if installed locally:

```bash
cd <project-root> && node node_modules/vue-auth-analyzer/scripts/vue-auth-api-analyzer.mjs --run-ai
```

This single command handles everything:
1. Static AST analysis (Vue SFC parsing, v-auth → @click → request() → HTTP method + URL)
2. Module grouping and AI task preparation
3. LLM analysis for unmatched buttons (cached modules are skipped)
4. Merging static + AI results into final report

**Do NOT add --ndjson.** Let progress output stream directly so the user can see it.

### Step 2: Present Results

Read the report via bash (not file read tools):

```bash
node -e "const d=require('.auth-analyzer/auth-mapping-merged.json'); console.log(JSON.stringify(d.stats, null, 2)); d.pages.forEach(p => { console.log('\n## ' + p.page); p.buttons.forEach(b => { const apis = b.apis.map(a => a.method + ' ' + a.url).join(', ') || '(UI only)'; console.log('  ' + b.authId + ' → ' + apis + ' [' + b.source + '/' + b.confidence + ']'); }); })"
```

Present to the user:
1. Coverage statistics
2. Per-page button-permission-API mapping table (with HTTP method + URL)
3. Low-confidence / failed entries
4. Recommendations

## Rules

- ❌ Do NOT read Vue files manually or grep for permission codes
- ❌ Do NOT generate Markdown reports — all output is JSON generated by the script
- ❌ Do NOT list function names as APIs — "app.getAppsList" is NOT an API mapping; it must be "GET /iam/apps"
- ❌ Do NOT run --static-only / --prepare-ai / --merge-ai separately — use --run-ai
- ❌ Do NOT write your own analysis or merge scripts

## Output Files

All output goes to `.auth-analyzer/` in the project root:

| File | Purpose |
|------|---------|
| `auth-mapping-merged.json` | **Final merged report** |
| `static/<module>.json` | Per-module static analysis |
| `ai-tasks/<module>.json` | Per-module AI tasks (with prompts) |
| `ai-results/<module>.json` | Per-module AI results |
| `.ai-auth-cache.json` | Incremental cache |

## Configuration

Edit `scripts/vue-auth-api-analyzer.mjs` CONFIG object or set environment variables:

| Config | Default | Description |
|--------|---------|-------------|
| `viewsDir` | `src/views` | Vue pages directory |
| `authDirectiveName` | `auth` | Directive name (use "permission" for v-permission) |
| `i18nFile` | `src/lang/package/zh-cn.ts` | i18n file path, null to skip |
| `excludePatterns` | `["**/components/**", ...]` | Glob patterns to exclude |
